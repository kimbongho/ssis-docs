## 1. OpenWebUI — AI 챗 인터페이스

### 1.1 접속
- 주소: `http://192.168.47.115:3000`
- 최초 접속 시 계정 생성(가입) 후 로그인. 이후 관리자가 사용자 가입 승인/권한 부여를 관리합니다.

### 1.2 기본 사용법
1. 로그인 후 상단/좌측 모델 선택 메뉴에서 사용할 모델을 선택합니다. 본 서버는 기본적으로 **`Qwen3.5-122B-A10B-FP8`** 모델(vLLM 서버에서 서빙) 하나로 구성되어 있습니다.
2. 하단 입력창에 질문/요청을 입력하고 전송하면 vLLM 서버가 응답을 생성합니다.
3. 대화는 좌측 사이드바에 채팅 세션 목록으로 저장되며, 이전 대화를 클릭해 이어서 진행할 수 있습니다.

### 1.3 주요 기능
| 기능 | 설명 |
|---|---|
| 새 채팅 | 좌측 상단 "새 채팅"으로 새 대화 시작 |
| 채팅 내 문서 첨부 | 파일(문서/이미지 등) 업로드 후 해당 문서 기반 질의 가능 (RAG) |
| 프롬프트 저장/공유 | 자주 쓰는 프롬프트를 템플릿으로 저장 가능 |
| 모델 파라미터 조정 | 채팅 설정에서 temperature 등 생성 파라미터 조정 가능 |
| 대화 내보내기 | 대화 기록을 내보내기(export) 가능 |

### 1.4 참고
- 본 배포는 vLLM 서버 하나만 백엔드로 연결되어 있어(모델 1종), Ollama 등 다른 백엔드는 비활성화(`ENABLE_OLLAMA_API: false`) 상태입니다.
- 최대 컨텍스트 길이는 서버 설정상 131,072 토큰까지 지원됩니다.

## 2. RAGFlow — 문서 기반 RAG 플랫폼

### 2.1 접속
- 웹 UI 주소: `http://192.168.47.115:8030`
- API 주소: `http://192.168.47.115:9380` (개발자/연동용)
- 최초 접속 시 관리자 계정 생성이 필요합니다(사용자 자가 가입도 허용되어 있음 — `REGISTER_ENABLED=1`).

### 2.2 기본 사용 흐름
1. **지식베이스(Knowledge Base) 생성**: 문서를 업로드할 저장소를 먼저 만듭니다.
2. **문서 업로드 및 파싱**: PDF/Word/PPT/텍스트 등 문서를 업로드하면 RAGFlow가 자동으로 청크 분할·인덱싱합니다(딥 문서 이해 기반 파싱).
3. **파싱 결과 확인/수정**: 청크 단위로 파싱 결과를 검토하고 필요 시 수동 수정할 수 있습니다.
4. **채팅 어시스턴트(Chat Assistant) 생성**: 만든 지식베이스를 연결하여 질의응답용 챗봇을 구성합니다. 이때 사용할 LLM(모델 프로바이더)을 지정해야 합니다.
5. **질의**: 챗봇 화면에서 질문하면 지식베이스 검색 결과를 근거로 한 답변과 출처(인용)가 함께 제공됩니다.

### 2.3 모델 프로바이더 설정 (관리자/설정 권한 필요)
RAGFlow는 자체 LLM을 내장하지 않으므로, 외부 모델을 연결해야 합니다. 본 환경에서는 사내 vLLM 서버를 OpenAI 호환 API로 등록해 사용하는 것을 권장합니다.
- API Base URL: `http://192.168.47.185:8100/v1`
- 모델명: `Qwen3.5-122B-A10B-FP8`
- API Key: 인증 미사용(내부망 전용) — `none` 또는 임의 값

### 2.4 주요 기능
| 기능 | 설명 |
|---|---|
| Agent(에이전트) | 여러 단계의 워크플로우(검색+생성+도구 호출 등)를 구성 |
| API 키 발급 | 외부 시스템 연동을 위한 API 키를 사용자별로 발급 |
| MCP 서버 | RAGFlow 기능을 MCP(Model Context Protocol)로 외부 도구에 노출 (설정 시 9382 포트) |
| Admin 콘솔 | 사용자/모델/시스템 설정 관리 (9381 포트, adminserver 활성화됨) |

### 2.5 참고
- 임베딩(문서 벡터화) 서비스가 현재 서버에 별도로 기동되어 있지 않습니다 — 임베딩 모델은 관리자가 설정에서 지정해야 정상 동작합니다([설치_매뉴얼](설치_매뉴얼_서버(VM_vLLM).md) §1.3 참고).
- 문서 검색 엔진은 Elasticsearch로 구성되어 있습니다.

## 3. GBrain — 지식 브레인

### 3.1 접속
- 주소: `http://192.168.47.115:8787`
- `/admin` 경로에서 관리 대시보드로 접속해 지식 페이지를 작성/조회합니다.

### 3.2 기본 사용법
- 하이브리드 검색(벡터 + BM25 키워드) 기반으로 질의 시 원시 문서가 아닌 **합성된 답변**(인용 포함)을 제공합니다.
- MCP(Model Context Protocol) 클라이언트로 연결하여 AI 에이전트의 "기억 계층"으로 활용할 수 있습니다.
