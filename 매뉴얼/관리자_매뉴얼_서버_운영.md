## 3. 상태 모니터링

### 3.1 컨테이너 상태
```bash
sudo docker ps -a --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
```
정상 상태 시 VM 서버는 `openwebui`, `compose-ragflow-cpu-1`, `compose-mysql-1`, `compose-es01-1`, `compose-minio-1`, `compose-redis-1`가 모두 `Up (healthy)`, vLLM 서버는 `vllm-qwen35-122b`가 `Up`이어야 합니다.

### 3.2 GPU 모니터링 (vLLM 서버)
```bash
nvidia-smi
# 또는 실시간 모니터링
watch -n 2 nvidia-smi
```
확인 포인트:
- GPU 0/1 모두 `VLLM::Worker_TP0`/`TP1` 프로세스가 각각 실행 중이어야 함(Tensor Parallel 2-way)
- VRAM 사용량이 설정된 `--gpu-memory-utilization 0.95` 근처(약 93GB/97GB)로 유지되는지 확인
- GPU 온도/전력이 비정상적으로 높지 않은지 확인

## 5. 백업

### 5.1 백업 대상
| 대상 | 경로 | 우선순위 |
|---|---|---|
| RAGFlow MySQL(메타데이터) | `/docker/data/ragflow/mysql` | 높음 |
| RAGFlow MinIO(원본 문서) | `/docker/data/ragflow/minio` | 높음 |
| RAGFlow Elasticsearch(인덱스) | `/docker/data/ragflow/elasticsearch` | 중간(재색인 가능) |
| OpenWebUI 데이터(대화/설정) | `/docker/data/openwebui` | 높음 |
| vLLM 모델 가중치 | `/data/models` | 낮음(재다운로드 가능하나 119GB로 시간 소요) |
| compose/.env 설정 파일 | `/docker/compose/**` | 높음(재구축 필수 자료) |

### 5.2 권장 백업 절차 (예시)
```bash
# MySQL 논리 백업 (권장 — 파일 복사보다 안전)
sudo docker exec compose-mysql-1 mysqldump -uroot -p'<비밀번호>' --all-databases > ragflow_mysql_backup_$(date +%F).sql

# 데이터 디렉터리 스냅샷 (서비스 중지 후 권장)
sudo docker compose -f /docker/compose/ragflow/docker-compose.yml stop
sudo tar czf ragflow_data_backup_$(date +%F).tar.gz /docker/data/ragflow
sudo docker compose -f /docker/compose/ragflow/docker-compose.yml start
```
> 실제 백업 주기·보관 정책·백업 저장소(별도 스토리지/오프사이트 여부)는 발주처 정책에 맞춰 별도 수립이 필요합니다.

## 6. 이미지/버전 업데이트

```bash
# 최신 이미지 가져오기
sudo docker compose -f <경로>/docker-compose.yml pull

# 재기동 (변경된 이미지로 컨테이너 재생성)
sudo docker compose -f <경로>/docker-compose.yml up -d
```
⚠️ 현재 OpenWebUI(`main`)와 vLLM(`latest`) 이미지는 태그가 고정되어 있지 않아, `pull` 시 예고 없이 버전이 바뀔 수 있습니다. **운영 환경에서는 태그를 특정 버전(예: `open-webui:v0.6.x`, `vllm-openai:v0.x.x`)으로 고정하고, 업데이트는 계획된 점검 시간에 수동으로 진행할 것을 권장합니다.**

## 7. 트러블슈팅

| 증상 | 점검 사항 |
|---|---|
| OpenWebUI에서 모델 응답 없음 | vLLM 컨테이너 상태(`docker ps`), vLLM 로그, `curl http://192.168.47.185:8100/v1/models` 응답 여부 확인. 네트워크 방화벽/라우팅 확인 |
| RAGFlow 문서 업로드/파싱 실패 | `compose-es01-1`, `compose-minio-1` healthy 상태 확인. MinIO 디스크 여유공간 확인 |
| RAGFlow 챗봇 응답 없음 | 챗봇에 연결된 모델 프로바이더(vLLM API) 설정이 올바른지 RAGFlow Admin에서 확인 |
| vLLM 컨테이너가 기동 후 바로 종료됨 | `docker logs vllm-qwen35-122b`에서 OOM(VRAM 부족) 여부 확인 — 다른 프로세스가 GPU를 점유하고 있지 않은지 `nvidia-smi`로 확인 |
| GPU 인식 안 됨(`nvidia-smi` 오류) | `nvidia-driver-open` 상태 확인, `sudo systemctl status nvidia-persistenced`, 커널 업데이트 후 DKMS 재빌드 필요 여부 확인 |
| 디스크 공간 부족 | `docker system df`로 미사용 이미지/볼륨 확인 후 `docker system prune`(⚠️ 사용 중인 리소스 오삭제 주의, 신중히 실행) |
